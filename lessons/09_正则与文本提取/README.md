# 模块 9：正则与文本提取

> 前面几个模块处理的都是"结构化数据"——HTML 有 BeautifulSoup 解析成树，JSON 有 json.loads 转成字典，表格有 csv/pandas。但现实里大量信息藏在"半结构化纯文本"里：日志、配置、邮件正文、PDF 抽出来的文字、用户输入。这些没有现成解析器，得自己描述"我要什么样的片段"。正则表达式（regular expression）就是干这个的：用一串模式描述一类字符串，让引擎帮你从文本里把所有匹配的片段捞出来。本模块从最基础的 match/search/findall 起步，到分组、替换、命名捕获，最后落到日志解析、提取 IP/邮箱/手机号/金额等实战场景。re 是 Python 标准库，不装任何东西，一定能跑。

## 核心库一览

| 库 | 来源 | 用途 | 推荐度 |
|---|:---:|---|:---:|
| `re` | 标准库 | 正则表达式匹配、查找、替换、分割 | ★★★★★ |
| `regex` | 第三方 | re 的超集，支持更宽 Unicode、可变长 lookbehind | ★★★ |

> 99% 的场景 `re` 标准库就够用了，本模块全部示例只用 `re`，零依赖。只有遇到 re 不支持的特性（比如可变长 lookbehind、`\p{Han}` 这种 Unicode 属性类）才需要装 `regex`：`uv add regex`，import 用 `import regex as re`，API 完全兼容。

## 正则 vs 字符串方法：什么时候用正则

**字符串方法**：`str.startswith`、`str.split`、`str.replace`、`in`、切片。简单直接，处理"固定字符串"最快。
```python
s = "2026-09-24"
if s.startswith("2026"):
    print("是今年")
parts = s.split("-")   # ['2026', '09', '24']
```

**正则**：处理"一类字符串"——模式里有变化的部分（数字几位、字母大小写、有没有空格）。
```python
import re
# 匹配任何 "年-月-日" 格式，不管具体数字
m = re.match(r"\d{4}-\d{2}-\d{2}", s)
# 从一段文本里捞出所有日期
re.findall(r"\d{4}-\d{2}-\d{2}", text)
```

| 对比项 | 字符串方法 | 正则 re |
|---|---|---|
| 适合场景 | 固定字符串、简单分割/替换 | 一类字符串、模式匹配、批量提取 |
| 学习成本 | 几乎为零 | 中（元字符、转义、贪婪要练） |
| 速度 | 快 | 快（编译后），但写复杂模式有回溯风险 |
| 可读性 | 高，一眼看懂 | 低，复杂模式像天书，必须写注释 |
| 灵活性 | 低，只能处理确切字符串 | 高，描述一类字符串 |

> **经验法则**：能用字符串方法解决就别上正则——`s.startswith("error")` 比 `re.match(r"error", s)` 清晰得多。一旦发现"我要找的东西格式不固定，但符合某种模式"（手机号、邮箱、IP、日期、金额、日志里的字段），就该用正则了。正则写出来一定要在旁边写注释说明匹配什么，过两个月自己也看不懂。

## 核心 API 速查

```python
import re

# --- 查找 ---
re.match(pattern, string)      # 从字符串开头匹配，匹配不到返回 None
re.search(pattern, string)     # 在任意位置搜索第一个匹配，匹配不到返回 None
re.findall(pattern, string)    # 返回所有匹配的列表（无组时是字符串列表，有组时是元组列表）
re.finditer(pattern, string)   # 返回迭代器，每个元素是 Match 对象（省内存）

# --- 替换与分割 ---
re.sub(pattern, repl, string)  # 把所有匹配替换成 repl，repl 里可用 \1 \2 引用分组
re.sub(pattern, repl, string, count=1)  # 只替换前 count 个
re.split(pattern, string)      # 按模式分割，比 str.split 更灵活（能按"一个或多个空格"切）

# --- 预编译（性能）---
pat = re.compile(pattern)      # 预编译成 Pattern 对象，重复使用更快
pat.match(string)              # 等价于 re.match(pattern, string)
pat.findall(string)            # 等价于 re.findall(pattern, string)

# --- Match 对象的方法 ---
m = re.search(r"(\d+)-(\d+)", "日期 09-24")
m.group()      # '09-24'  整个匹配
m.group(0)     # '09-24'  同上
m.group(1)     # '09'     第 1 个捕获组
m.group(2)     # '24'     第 2 个捕获组
m.groups()     # ('09', '24')  所有组
m.start()      # 匹配起始位置
m.end()        # 匹配结束位置
m.span()       # (start, end)

# --- 常用标志 ---
re.IGNORECASE  # 忽略大小写（也可写 re.I）
re.MULTILINE   # ^ $ 匹配每行开头结尾（而非整个字符串）
re.DOTALL      # . 也匹配换行符（默认不匹配）
re.VERBOSE     # 允许模式里写空白和注释，提高可读性
```

常用元字符速查表：

| 元字符 | 含义 | 示例 | 匹配 |
|:---:|---|---|---|
| `.` | 任意一个字符（不含换行） | `a.c` | `abc`, `a1c`, `a c` |
| `*` | 前一个 0 次或多次 | `ab*c` | `ac`, `abc`, `abbbc` |
| `+` | 前一个 1 次或多次 | `ab+c` | `abc`, `abbbc`（不匹配 `ac`） |
| `?` | 前一个 0 次或 1 次 | `ab?c` | `ac`, `abc` |
| `*?` `+?` | 非贪婪版本（尽量少匹配） | `a.*?b` | `aXXb` 而非 `aXXbYYb` |
| `^` | 字符串/行开头 | `^Hello` | `Hello` 在开头才匹配 |
| `$` | 字符串/行结尾 | `end$` | `end` 在结尾才匹配 |
| `\d` | 数字 0-9 | `\d+` | `123`, `7` |
| `\D` | 非数字 | `\D+` | `abc`, `  ` |
| `\w` | 字母数字下划线 | `\w+` | `hello_1` |
| `\W` | 非字母数字下划线 | `\W` | ` `, `!`, `@` |
| `\s` | 空白（空格/制表/换行） | `\s+` | ` `, `\t`, `\n  ` |
| `\S` | 非空白 | `\S+` | `abc` |
| `[...]` | 字符集，匹配其中任一 | `[aeiou]` | `a`, `e`, `i` |
| `[^...]` | 字符集取反 | `[^0-9]` | 任何非数字 |
| `{n}` `{m,n}` | 重复 n 次 / m 到 n 次 | `\d{4}` `\d{2,4}` | `2026` / `09` 到 `1234` |
| `(...)` | 捕获组 | `(\d+)-(\d+)` | 捕获两个数字 |
| `(?:...)` | 非捕获组（不编号） | `(?:ab)+` | `ab`, `abab` |
| `(?P<name>...)` | 命名捕获组 | `(?P<year>\d{4})` | 用 `m.group("year")` 取 |
| `\1` `\2` | 反向引用前面捕获组 | `(\w+)\s\1` | `hello hello` |
| `|` | 或 | `cat\|dog` | `cat` 或 `dog` |

> **转义提醒**：在 Python 里写正则一律用 **r-string**（`r"\d+"`），否则 `\d` 会被 Python 当成普通转义符处理。要匹配元字符本身（`. * + ? $` 等）就加反斜杠转义：`r"\."` 匹配真正的点，`r"\$"` 匹配美元符号。

## 底层原理（简单了解）

1. **回溯匹配引擎**：Python 的 `re` 用的是 NFA（非确定有限自动机）+ 回溯算法，不是 DFA。意思是它遇到歧义时会"试一条路，走不通就退回来换一条"。绝大多数模式这没问题，但有些写法会让回溯指数级爆炸——最经典的是嵌套量词 `(a+)+` 配上不匹配的字符串，长度 30 的字符串能让引擎跑几亿次。这叫"灾难性回溯"（catastrophic backtracking）。**对策**：尽量用具体字符集代替 `.*`（用 `[^<>]+` 匹配标签内容），用非贪婪 `*?` 限定范围，超长文本考虑用 `regex` 库或换思路。
2. **compile 预编译提升性能**：每次调 `re.match(pattern, s)`，Python 都要先解析 `pattern` 字符串、构建状态机，再开始匹配。模式固定、要匹配几千几万次时，这步重复开销很大。`pat = re.compile(pattern)` 把模式预先编译成 `Pattern` 对象，之后调 `pat.match(s)` 跳过解析，直接匹配。`re` 模块内部有个 LRU 缓存（默认 512 个模式），所以偶尔调用不 compile 也几乎没差别——**只在循环里高频调用、或想明确表达"这个模式是常量"时才需要手动 compile**。
3. **贪婪 vs 非贪婪**：`*` `+` `?` 默认是"贪婪"的——尽量多匹配。`a.*b` 在 `aXbYb` 上会匹配整个 `aXbYb`（一直找到最后一个 b）。加个 `?` 变成"非贪婪"——尽量少匹配：`a.*?b` 只匹配 `aXb`（找到第一个 b 就停）。提取 HTML 标签内容、引号字符串这类"有明确结束标志"的场景必须用非贪婪，否则会一路吃到下一个结束标志。**经验**：能用非贪婪就用非贪婪，贪婪匹配出 bug 的概率高得多。
4. **match vs search 的坑**：`re.match` 只从字符串**开头**匹配，相当于自带 `^`；`re.search` 在**任意位置**搜索第一个匹配。新手常以为 `re.match(r"\d+", "abc123")` 能匹配 123，其实返回 None——它要求从头就是数字。要"在任意位置找"就用 `re.search` 或 `re.findall`。`re.fullmatch` 是第三个选择：要求整个字符串都匹配，等价于前后都加 `^` `$`。
