# 最佳实践与常见陷阱

> 学完 13 个模块后，这份文档帮你把零散知识串起来：什么场景选什么库、怎么写才规范、哪些坑别踩。

## 一、选型速查表

| 场景 | 首选 | 备选 | 不推荐 |
|---|---|---|---|
| 路径操作 | `pathlib` | `os.path` | 手拼字符串路径 |
| 批量移动/复制 | `shutil` | `pathlib` | `os.system("mv ...")` |
| 读写 CSV | `csv` 标准库 | `pandas`（要分析时） | 手动 split(",") |
| 读写 Excel | `openpyxl` | `pandas`（要分析时） | xlrd（已停更） |
| 数据分析汇总 | `pandas` | — | 纯 Python 循环（慢） |
| HTTP 请求 | `requests` | `urllib`（无依赖时） | `os.system("curl ...")` |
| HTML 解析 | `beautifulsoup4` | `lxml`（要速度时） | 正则提取 HTML |
| 浏览器自动化 | `selenium` | `playwright`（更新更快） | — |
| 定时任务 | `schedule` | `time.sleep`（简单场景） | `threading.Timer`（不精确） |
| 文件监控 | `watchdog` | `time.sleep` 轮询（差但简单） | — |
| Word 操作 | `python-docx` | — | 直接改 XML |
| PPT 操作 | `python-pptx` | — | — |
| PDF 提取 | `pdfplumber` | `PyMuPDF`（更快） | — |
| 邮件发送 | `yagmail` | `smtplib`（无依赖时） | — |
| 图像处理 | `Pillow` | `OpenCV`（要 CV 算法时） | — |
| 数据库 | `sqlite3`（轻量） | `sqlalchemy`（ORM） | 直接拼 SQL 字符串 |
| 正则提取 | `re` | — | 手写字符串查找 |
| 桌面自动化 | `pyautogui` | — | — |

### 选型原则

1. **标准库优先**：能用标准库解决的，不引第三方。如简单 CSV 用 `csv`，简单 HTTP 用 `urllib`。
2. **按需求复杂度升级**：简单读写用 `csv`/`openpyxl`，要分组汇总统计分析才上 `pandas`。
3. **看维护活跃度**：选还在更新的库。`xlrd` 已停更（不支持 xlsx），改用 `openpyxl`。
4. **看依赖体积**：`pandas` 依赖 numpy（几十MB），如果只需读写 Excel 用 `openpyxl` 更轻。

## 二、最佳实践

### 1. 路径处理：永远用 pathlib

```python
# 好 —— 跨平台、可读
from pathlib import Path
data_file = Path(__file__).parent / "data" / "input.csv"

# 差 —— Windows 能跑，Linux 挂
data_file = "data\\input.csv"

# 差 —— 拼接容易出错
import os
data_file = os.path.dirname(__file__) + "/data/input.csv"
```

**关键技巧**：用 `Path(__file__).parent` 定位脚本所在目录，不依赖当前工作目录。

### 2. 编码：统一 UTF-8

```python
# 读写文件永远指定 encoding
text = Path("file.txt").read_text(encoding="utf-8")
Path("file.txt").write_text(content, encoding="utf-8")

# CSV 读写
with open("data.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
```

**Windows 坑**：Windows 默认编码是 GBK，不指定 encoding 中文必乱码。CSV 写入加 `newline=""` 防止 Windows 多出空行。

### 3. 异常处理：别让脚本裸奔

```python
# 网络请求必须 try/except
import requests
try:
    resp = requests.get(url, timeout=10)
    resp.raise_for_status()
except requests.Timeout:
    print("请求超时，请检查网络")
except requests.ConnectionError:
    print("无法连接，请检查网络或 VPN")
except requests.HTTPError as e:
    print(f"服务器返回错误: {e}")
```

**原则**：网络、文件操作、外部命令，这三类永远要处理异常。

### 4. 资源管理：用 with 上下文管理器

```python
# 好 —— 自动关闭
with open("file.txt", encoding="utf-8") as f:
    content = f.read()

# 好 —— 数据库自动提交/回滚
with conn:
    conn.execute("INSERT INTO ... VALUES (?, ...)", data)

# 差 —— 忘了关
f = open("file.txt")
content = f.read()
# f.close() 忘了写
```

### 5. 参数化查询：防 SQL 注入

```python
# 好 —— 参数化
cursor.execute("SELECT * FROM users WHERE name = ?", (name,))

# 差 —— 字符串拼接，有注入风险
cursor.execute(f"SELECT * FROM users WHERE name = '{name}'")
```

### 6. 命令行工具：用 argparse

```python
import argparse
parser = argparse.ArgumentParser(description="文件统计工具")
parser.add_argument("directory", help="要统计的目录")
parser.add_argument("--verbose", "-v", action="store_true", help="详细输出")
args = parser.parse_args()
```

**好处**：自动生成 `--help`，参数校验，比手动解析 `sys.argv` 可靠得多。

### 7. 批量操作：先收集再处理

```python
# 好 —— 先收集文件列表，再循环处理
files = list(Path("data").glob("*.csv"))
for f in files:
    process(f)

# 危险 —— 边遍历边删除/移动，可能跳过文件或报错
for f in Path("data").iterdir():
    f.unlink()
```

### 8. 日志：用 logging 而非 print

```python
import logging
logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
logging.info("开始处理")
logging.error("文件不存在: %s", filepath)
```

**print 的问题**：没法控制级别、没法输出到文件、没时间戳。正式脚本用 logging。

### 9. 配置与代码分离

```python
# 好 —— 配置放 .env 或 config.ini
from pathlib import Path
import configparser

config = configparser.ConfigParser()
config.read("config.ini")
api_key = config["api"]["key"]

# 差 —— 硬编码
api_key = "sk-1234567890abcdef"
```

### 10. 幂等设计：脚本可重复运行

```python
# 好 —— 目录已存在不报错
Path("output").mkdir(parents=True, exist_ok=True)

# 好 —— 文件存在就跳过
if not output_file.exists():
    generate(output_file)
```

**教学脚本尤其重要**：学习者会反复运行，每次都该正常工作。

## 三、常见陷阱

### 陷阱 1：Windows 路径分隔符

```python
# Windows 路径用反斜杠，但 Python 字符串里 \ 是转义
path = "C:\new\folder"   # \n 被转义成换行！

# 解决：用 r 原始字符串，或用 pathlib
path = r"C:\new\folder"
path = Path("C:/new/folder")  # pathlib 正斜杠也行
```

### 陷阱 2：CSV 中文乱码 + 空行

```python
# Windows 写 CSV 不加 newline="" 会多空行
# 不加 encoding 会乱码
with open("data.csv", "w", encoding="utf-8-sig", newline="") as f:
    writer = csv.writer(f)
```

**utf-8-sig vs utf-8**：`utf-8-sig` 带 BOM 头，Excel 打开不乱码，但纯程序读可能多3字节。一般用 `utf-8`，要给 Excel 用就 `utf-8-sig`。

### 陷阱 3：openpyxl 公式读出来是 None

```python
# 写了公式 =A1+B1，用 openpyxl 读出来是公式字符串而非计算结果
# 因为 openpyxl 不计算公式，只有 Excel 打开过才会算
# 解决：用 data_only=True 读，但前提是文件被 Excel 保存过
wb = openpyxl.load_workbook("data.xlsx", data_only=True)
```

### 陷阱 4：requests 不设超时

```python
# 差 —— 服务器不响应就永远卡着
requests.get(url)

# 好 —— 必须设超时
requests.get(url, timeout=10)
```

### 陷阱 5：subprocess 的 shell=True 注入风险

```python
# 危险 —— 用户输入可注入命令
subprocess.run(f"echo {user_input}", shell=True)
# 如果 user_input = "; rm -rf /"，就完了

# 安全 —— 不用 shell，传列表
subprocess.run(["echo", user_input])
```

### 陷阱 6：selenium 忘了 quit

```python
# 差 —— 异常时 driver 不会关闭，浏览器进程残留
driver = webdriver.Chrome()
driver.get(url)
# 如果这里出错，driver.quit() 不会执行

# 好 —— 用 with 或 try/finally
driver = webdriver.Chrome()
try:
    driver.get(url)
    # 操作...
finally:
    driver.quit()
```

### 陷阱 7：pyautogui 操控鼠标键盘

```python
# 危险 —— 脚本真的会移动鼠标、点击、打字
import pyautogui
pyautogui.FAILSAFE = True   # 必须设！鼠标移到左上角能紧急停止
pyautogui.PAUSE = 0.5       # 每个操作暂停0.5秒，能看清在做什么
```

**建议**：开发时先用 print 模拟，确认逻辑对了再真跑。

### 陷阱 8：pandas 修改 SettingWithCopyWarning

```python
# 可能触发警告
df[df['age'] > 18]['name'] = 'adult'

# 正确写法
df.loc[df['age'] > 18, 'name'] = 'adult'
```

### 陷阱 9：正则贪婪匹配

```python
import re
text = "<div>内容1</div><div>内容2</div>"

# 贪婪 —— 匹配到最后一个 </div>
re.findall(r"<div>(.*)</div>", text)  # ['内容1</div><div>内容2']

# 非贪婪 —— 匹配到最近的 </div>
re.findall(r"<div>(.*?)</div>", text)  # ['内容1', '内容2']
```

### 陷阱 10：文件编码不是 UTF-8

```python
# 有些旧文件是 GBK 编码，用 utf-8 读会报错
# 解决：先试 utf-8，失败再试 gbk
try:
    text = Path("file.txt").read_text(encoding="utf-8")
except UnicodeDecodeError:
    text = Path("file.txt").read_text(encoding="gbk")
```

## 四、项目结构建议

一个正式的自动化脚本项目，建议这样组织：

```
my-project/
├── pyproject.toml          # 依赖管理
├── config.ini              # 配置文件（不放代码里）
├── src/
│   └── my_script/
│       ├── __init__.py
│       ├── main.py         # 入口
│       └── utils.py        # 工具函数
├── data/                   # 输入数据
├── output/                 # 输出结果
└── tests/                  # 测试
```

**关键原则**：
- 配置和代码分离
- 输入和输出分离
- 脚本可重复运行（幂等）
- 有异常处理和日志
- 用 `uv` 或 `venv` 管理依赖，不污染全局环境
